# Flow

Локальное веб-приложение для 2–10 человек: добавить друга по нику Last.fm, загрузить его
прослушивания и посмотреть отчёт (топ артистов, часы прослушивания, сходство вкусов, матрица
«человек × артист»). Только локальный запуск, без деплоя.

## Запуск

Нужны Python 3.12+ и Node 20+.

```bash
# 1. Один раз: окружение и зависимости
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
(cd web && npm install)

# 2. Один раз: настройки
cp .env.example .env     # впишите LASTFM_KEY и ADMIN_PIN
```

Два терминала в папке проекта:

```bash
# бэкенд (http://127.0.0.1:8000, документация на /docs)
.venv/bin/uvicorn flow.api:app --reload --host 127.0.0.1 --port 8000 --app-dir src

# фронтенд
cd web && npm run dev     # http://127.0.0.1:5173
```

Откройте http://127.0.0.1:5173, нажмите «Я Анна», введите PIN. Дальше «Люди»: добавьте
друга и нажмите «Синхронизировать».

Тесты: `.venv/bin/python -m pytest`. Типы фронтенда: `cd web && npm run typecheck`.

### Настройки (`.env`, в git не попадает)

| Переменная | Зачем |
|---|---|
| `LASTFM_KEY` | Ключ Last.fm API. Без него не работают добавление и синхронизация. |
| `ADMIN_PIN` | PIN входа. Не задан: вход выключен (503). Значения по умолчанию нет. |
| `SIGNUP_ENABLED` | `1` включает публичные заявки `/api/signup`. По умолчанию выключено (404). |
| `DB_PATH` | Путь к базе. По умолчанию `data/flow.db`. |

## Структура

```
src/flow/config.py     настройки из окружения (+ .env через python-dotenv)
src/flow/storage.py    весь SQL (sqlite3): scrobbles, people, signup_requests
src/flow/lastfm.py     клиент Last.fm, sync_user / sync_all (ошибка одного не останавливает других)
src/flow/analytics.py  чистые функции: сводка, статистика, Jaccard, матрица
src/flow/auth.py       токены входа и ограничитель частоты (в памяти)
src/flow/api.py        FastAPI, тонкий слой над модулями
scripts/               обёртки: pull_lastfm.py, make_report.py (статичный HTML-отчёт)
web/                   Vite + React + TypeScript
tests/                 pytest (сеть в тестах запрещена)
docs/decisions.md      принятые решения
```

Зависимости идут только вниз: `api` → `lastfm`/`analytics`/`auth` → `storage` → `config`.

## API

Всё под `/api`. Адреса, кроме `health`, `auth` и `signup`, требуют `Authorization: Bearer <token>`,
иначе 401. Защита стоит на уровне роутера, поэтому новый закрытый адрес защищён автоматически.

| Метод и адрес | Описание |
|---|---|
| `GET /health` | `{status:"ok"}` |
| `POST /auth` `{pin}` | `{token}`. 5 попыток в минуту с адреса, дальше 429. Токен живёт 12 часов, хранится в памяти сервера. |
| `POST /signup` `{username, consent:true, contact?}` | Публичная заявка друга (нужен `SIGNUP_ENABLED=1`). Всегда отвечает `{status:"received"}`, ничего не сообщая о других людях. |
| `GET /people` | `[{username, display_name, plays, last_synced_at, status, error}]` |
| `POST /people` `{username, display_name}` | Проверяет ник через Last.fm и добавляет. 404 нет такого ника, 409 уже есть. |
| `DELETE /people/{username}` | Удаляет человека, все его прослушивания и заявки (204). |
| `POST /sync` `{username?}` | `{results:[{username, added, status, error?}]}`. Блокирующий: ответ приходит, когда загрузка закончилась. |
| `GET /signups` | Ожидающие заявки. |
| `POST /signups/{id}/approve`, `/reject` | Принять (человек попадает в people) или отклонить. Контакт стирается. |
| `GET /report` | `{generated_at, summary, users, similarity, matrix}`, формат в `web/src/types.ts`. |

Статусы человека: `ok`, `private` (закрытый профиль), `not_found`, `error`. Ошибки приходят как
`{detail: "текст"}`; ошибки валидации (422) как `{detail: [{msg, …}]}`.

## Приватность

- `data/`, `.env*`, `.venv`, `node_modules` в `.gitignore`. Ключей и реальных данных в репозитории нет.
- Бэкенд и Vite слушают только `127.0.0.1`; CORS разрешён только для адреса Vite.
- Берутся только имена артистов, названия треков и время прослушивания. Удаление человека
  стирает все его данные (отзыв согласия).
- Публичная заявка: honeypot, ограничение длины и частоты, потолок ожидающих заявок; на повторную
  заявку и на уже добавленного человека ответ одинаковый.

## Известные ограничения

- Коды ошибок Last.fm для статусов `not_found` (6) и `private` (17) в официальной документации
  описаны иначе и держатся на наблюдаемом поведении. Ник, которого нет, на живом Last.fm
  определяется верно; закрытый профиль живьём пока не проверен.
- Токены и лимиты частоты живут в памяти: после перезапуска сервера нужно войти заново.
- Часы в графиках считаются по часовому поясу сервера.
- Лимит заявок считается по адресу клиента; за прокси (туннель, деплой) его нужно доработать.
- Деплой не предусмотрен: нужен HTTPS, постоянный диск и один процесс.
